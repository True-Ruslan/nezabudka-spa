# Nepomka v0.2 — Service pages, SEO structure and release design

Дата: 2026-09-07  
Статус: **approved / implemented in v0.2 branch**

## Цель

v0.2 переводит Nepomka от одной коммерческой landing-page к небольшой статической SEO-структуре с отдельными страницами ключевых услуг, не меняя визуальную систему и не добавляя неподтверждённые данные.

Release criteria: four service routes, общий homepage SEO-title, base-path safety, сохранённая конверсия и release только после successful merge/main CI/production deployment.

## Scope

Публичные routes:

- `/avtopodbor/`;
- `/proverka-avto/`;
- `/bronirovanie-plenkoy/`;
- `/tonirovka/`.

Разбор сметы и сравнение запчастей остаются на главной без отдельных thin pages.

Homepage title: `Nepomka — автомобильный специалист в Белгороде`.

Все шесть offer-карточек сохраняются. Четыре ключевые карточки получают secondary `Подробнее об услуге`, а существующий contact CTA остаётся primary conversion path.

## Data architecture

`src/data/site.ts` остаётся source of truth для offer ID, цены, режима, краткой формулировки, условий и CTA.

`src/data/service-pages.ts` содержит только page-specific `seoTitle`, `seoDescription`, `lead`, `included`, `workflow`, `limitations`, `faq` и связан с offer по стабильному `offerId`.

Цена/режим не дублируются в двух источниках.

## Page architecture

Один reusable `ServiceDetail.astro` принимает offer + config. Четыре explicit Astro route files предпочтительнее catch-all: они не конфликтуют с `/cases/` и custom 404 и делают public URL contract очевидным.

Service pages переиспользуют `BaseLayout`, Header, Contact и Footer. CTA ведёт на локальный `#contact`; `← Все услуги` возвращает на `${base}#expertise`.

## SEO / structured data

Главная сохраняет Person/Offer JSON-LD. Service pages добавляют отдельный Service JSON-LD.

Каждая detail page имеет unique title/description/canonical. Для услуг с ценой `от` fixed `price` в schema не публикуется.

Canonical формируется из текущего pathname/Astro.site и должен работать в двух build modes:

- Project Pages: `https://true-ruslan.github.io/nezabudka-spa/...`;
- custom domain: `https://nepomka.ru/...`.

Sitemap включает четыре routes.

## Verification contract

Playwright проверяет homepage title, четыре routes, metadata/canonical, Service JSON-LD, base-safe links, contact conversion, external-link security и mobile overflow.

Static verifier требует:

- `avtopodbor/index.html`;
- `proverka-avto/index.html`;
- `bronirovanie-plenkoy/index.html`;
- `tonirovka/index.html`;
- корректный canonical каждого route.

CI дополнительно проверяет Project Pages/custom-domain canonical и sitemap. Production deploy делает representative smoke `/avtopodbor/` вместе с home и real-404 smoke.

## Integrity constraints

v0.2 не добавляет:

- fabricated cases/reviews;
- customer counts;
- неподтверждённые сертификаты/гарантии;
- analytics/cookies;
- form/backend/CMS/UI framework;
- repository rename;
- отдельные страницы двух consultation-only offers.

## Repository / release policy

`main` защищён active ruleset: PR, required `quality`, CodeQL high-or-higher, linear history, no deletion/non-fast-forward. Merge settings — squash-only; auto-merge/update branch/automatic branch deletion включены.

Project marker: `0.2.0` в manifest + lockfile.

Release sequence:

1. feature PR;
2. `quality` + CodeQL green;
3. squash merge;
4. post-merge main CI green;
5. Pages build/deploy/smoke green;
6. verify `https://nepomka.ru/` + representative service route;
7. tag `v0.2.0` на deployed merge commit;
8. GitHub Release `v0.2.0`.

Tag/release никогда не создаются на feature head до production confirmation.
