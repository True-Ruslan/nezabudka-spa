# v0.2.1 — Indexing & Service Discoverability

Дата: 2026-09-08

## Контекст

Nepomka уже имеет production-домен `https://nepomka.ru/`, четыре отдельные service pages, sitemap, canonical URL, Service JSON-LD, Playwright desktop/mobile coverage и gated GitHub Pages deployment. Следующий безопасный шаг — усилить техническую индексируемость и внутреннюю связность существующих страниц без создания тонкого SEO-контента, вымышленных кейсов или неподтверждённых данных.

## Цель

Сделать существующие страницы услуг проще для обхода поисковыми роботами и навигации пользователями, сохранив текущую статическую Astro/GitHub Pages архитектуру и единые источники фактических данных.

## Не входит в scope

- новые SEO-landing pages;
- блог/статьи;
- аналитика, Search Console и Яндекс Вебмастер;
- реальные кейсы/отзывы/рабочие фотографии без исходных материалов и разрешения;
- изменение цен, услуг, контактов, позиционирования или brand assets;
- backend или формы заявок.

## Архитектура

Изменения остаются полностью статическими и build-time.

1. `robots.txt` становится генерируемым Astro endpoint, чтобы `Sitemap:` автоматически соответствовал текущему `Astro.site` и base path.
2. Service pages получают видимый breadcrumb и schema.org `BreadcrumbList`.
3. `ServiceDetail.astro` получает блок `Другие услуги`, который строится из существующих `offers` и показывает остальные ключевые service pages.
4. Все ссылки формируются base-safe через `import.meta.env.BASE_URL`; цены и названия не дублируются в новом источнике данных.
5. CI/static verifier/Playwright проверяют оба режима публикации: GitHub Project Pages и custom domain.

## Robots / sitemap

Текущий статический `public/robots.txt` заменяется build-time route `src/pages/robots.txt.ts`.

Ожидаемый production output для custom domain:

```text
User-agent: *
Allow: /
Sitemap: https://nepomka.ru/sitemap-index.xml
```

Для Project Pages output должен учитывать site origin и base path, например:

```text
Sitemap: https://true-ruslan.github.io/nezabudka-spa/sitemap-index.xml
```

URL sitemap должен вычисляться из текущей Astro-конфигурации, а не храниться отдельной строковой константой. `robots.txt` остаётся `text/plain; charset=utf-8`.

## Breadcrumbs

Каждая из четырёх service pages получает небольшой breadcrumb над основным hero-контентом:

`Главная → <Название услуги>`

Требования:

- `Главная` — ссылка на base root;
- текущая услуга — текст, не ссылка;
- breadcrumb имеет semantic `nav` с понятным `aria-label`;
- мобильная версия не создаёт horizontal overflow;
- визуально breadcrumb не конкурирует с `Все услуги`, поэтому существующий back-link заменяется breadcrumb-навигацией, а не дублируется рядом.

## BreadcrumbList structured data

Для каждой service page публикуется дополнительный JSON-LD объект `BreadcrumbList`:

1. `Главная` → canonical homepage URL;
2. текущая service page → её canonical URL.

Structured data должен собираться из текущего route/config, без ручного копирования URL между четырьмя страницами.

Чтобы избежать нескольких слабо связанных JSON-LD вставок, service page должна передавать в layout массив дополнительных structured-data объектов либо `@graph`. Рекомендуемый вариант — расширить `BaseLayout` до поддержки массива объектов и оставить существующий Person JSON-LD независимым.

## Блок «Другие услуги»

После FAQ и до contact section на каждой detail page добавляется блок `Другие услуги`.

Правила:

- показываются только offers, у которых есть `pagePath`;
- текущая услуга исключается;
- остаются ровно три ссылки на другие ключевые направления;
- карточки используют `offer.title`, `offer.price`, `offer.mode` из `src/data/site.ts`;
- не добавляется новый маркетинговый текст, которого нет в factual source;
- карточка ведёт на base-safe detail route;
- блок должен выглядеть как продолжение текущей editorial/grid-системы, а не как отдельный рекламный виджет;
- на mobile карточки складываются в одну колонку без overflow.

## Данные и границы ответственности

`src/data/site.ts` остаётся source of truth для:

- title услуги;
- price / priceValue;
- mode;
- pagePath;
- prepare.

`src/data/service-pages.ts` остаётся source of truth для page-specific SEO/detail copy.

Новый отдельный массив service-navigation создавать не нужно: список связанных услуг вычисляется из `offers`.

## Компоненты и предполагаемые файлы

Ожидаемые изменения:

- удалить `public/robots.txt`;
- добавить `src/pages/robots.txt.ts`;
- `src/layouts/BaseLayout.astro` — поддержка нескольких дополнительных JSON-LD объектов;
- `src/components/ServiceDetail.astro` — breadcrumb + `Другие услуги`;
- четыре route-файла service pages — BreadcrumbList и передача structured data;
- при необходимости небольшой reusable helper для canonical/base-safe URL, только если он реально устраняет дублирование;
- `scripts/verify-static-build.mjs`;
- Playwright tests;
- `.github/workflows/ci.yml` и/или deploy smoke только если текущие команды не покрывают новые assertions;
- `docs/PROJECT_STATE.md`, `docs/ROADMAP.md`, `docs/CHANGELOG.md`, при необходимости README.

## Ошибки и fail-fast

Build/CI должен падать, если:

- `robots.txt` не содержит sitemap URL, соответствующий текущему site/base;
- sitemap URL указывает не на существующий generated sitemap index;
- service page теряет canonical URL;
- breadcrumb home link не base-safe;
- `BreadcrumbList` содержит неправильный homepage/service URL;
- `Другие услуги` содержит текущую услугу, не содержит все три остальные service routes или создаёт broken internal link;
- изменения создают mobile horizontal overflow.

## Тестирование — TDD

Реализация начинается с regression tests, которые на текущем `main` должны падать по ожидаемым причинам.

Минимальный набор GREEN-проверок:

1. `robots.txt` содержит правильный `Sitemap:` в Project Pages build.
2. `robots.txt` содержит `https://nepomka.ru/sitemap-index.xml` в custom-domain build.
3. static verifier подтверждает существование target sitemap и корректность service outputs.
4. каждая service page имеет semantic breadcrumb `Главная → текущая услуга`.
5. каждая service page публикует корректный `BreadcrumbList`.
6. блок `Другие услуги` содержит ровно три другие ключевые service pages и исключает текущую.
7. ссылки работают с Project Pages base path.
8. mobile service pages не имеют horizontal overflow.
9. существующие contact CTA, Telegram/MAX, цены, FAQ, SEO title/description/canonical и Service JSON-LD не регрессируют.

## Production verification

После merge в `main`:

1. main CI и CodeQL должны быть зелёными;
2. deploy запускается только существующим `workflow_run` gate;
3. production smoke проверяет `https://nepomka.ru/robots.txt` и representative service page;
4. smoke подтверждает `Sitemap: https://nepomka.ru/sitemap-index.xml`;
5. representative service page содержит breadcrumb и ссылку как минимум на одну другую service page;
6. реальный 404 smoke остаётся зелёным.

## Критерии готовности

v0.2.1 готов, когда:

- `robots.txt` environment-aware и указывает на фактический sitemap index;
- все четыре service pages имеют видимые breadcrumbs и `BreadcrumbList`;
- все четыре service pages имеют блок из трёх других ключевых услуг;
- нет нового неподтверждённого маркетингового контента;
- Project Pages и custom-domain builds проходят одинаково;
- full Playwright/static-verifier/CodeQL green;
- merge выполнен через PR и production smoke подтверждает новую функциональность на `nepomka.ru`.
