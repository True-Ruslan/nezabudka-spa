# v0.2.1 Indexing & Service Discoverability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Усилить индексируемость и внутреннюю навигацию четырёх существующих service pages Nepomka без новых SEO-страниц, неподтверждённого контента или backend.

**Architecture:** Оставить решение полностью статическим и build-time. Генерировать `robots.txt` из Astro config/site/base, централизовать Service + Breadcrumb structured data в небольшом helper, расширить `ServiceDetail.astro` видимым breadcrumb и блоком связанных услуг, затем усилить static verifier, Playwright, CI и production smoke.

**Tech Stack:** Astro 7.3.x, TypeScript 5.9.x, Node.js 24, Playwright 1.55.x, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-08-v0.2.1-indexing-discoverability-design.md`

## Global Constraints

- Production URL остаётся `https://nepomka.ru/`.
- Архитектура остаётся статической Astro/GitHub Pages; backend не добавляется.
- Новые SEO landing pages, блог и статьи не входят в scope.
- Реальные кейсы, отзывы и рабочие фотографии не публикуются без исходных материалов и разрешения.
- Цены, `title`, `mode`, `pagePath` и `prepare` услуг остаются в `src/data/site.ts` как едином factual source.
- Page-specific SEO/detail copy остаётся в `src/data/service-pages.ts`.
- Новая service-navigation не получает отдельный массив данных; она вычисляется из `offers`.
- Контакты, Telegram/MAX, Instagram, цены, позиционирование и утверждённые brand assets не меняются.
- Все internal URLs обязаны работать и при Project Pages base `/nezabudka-spa/`, и при custom-domain base `/`.
- Реализация ведётся TDD: failing regression → подтверждённый RED → minimal implementation → GREEN → commit.
- Merge только через PR после `quality` + CodeQL; production deploy только через существующий successful-main-CI `workflow_run` gate.

```ts
import type { APIRoute } from 'astro';

export const prerender = true;

export const GET: APIRoute = ({ site }) => {
  if (!site) throw new Error('Astro site URL is required to generate robots.txt');

  const base = import.meta.env.BASE_URL;
  const home = new URL(base, site);
  const sitemap = new URL('sitemap-index.xml', home);
  const body = `User-agent: *\nAllow: /\nSitemap: ${sitemap.href}\n`;

  return new Response(body, {
    headers: { 'Content-Type': 'text/plain; charset=utf-8' },
  });
};
```

- [ ] **Step 3: Create shared structured-data builder**

Create `src/lib/service-structured-data.ts`:

```ts
import type { ServicePageConfig } from '../data/service-pages';
import { brand, offers } from '../data/site';

type Offer = (typeof offers)[number];

type Input = Readonly<{
  offer: Offer;
  config: ServicePageConfig;
  site: URL;
  base: string;
}>;

export function buildServiceStructuredData({ offer, config, site, base }: Input) {
  if (!offer.pagePath) {
    throw new Error(`Offer ${offer.id} does not have a service page path`);
  }

  const homeUrl = new URL(base, site).href;
  const serviceUrl = new URL(offer.pagePath, homeUrl).href;

  const service = {
    '@context': 'https://schema.org',
    '@type': 'Service',
    name: offer.title,
    description: config.seoDescription,
    areaServed: { '@type': 'City', name: 'Белгород' },
    provider: {
      '@type': 'Person',
      name: brand.person,
      alternateName: brand.name,
      url: homeUrl,
    },
  };

  const breadcrumb = {
    '@context': 'https://schema.org',
    '@type': 'BreadcrumbList',
    itemListElement: [
      { '@type': 'ListItem', position: 1, name: 'Главная', item: homeUrl },
      { '@type': 'ListItem', position: 2, name: offer.title, item: serviceUrl },
    ],
  };

  return [service, breadcrumb] as const;
}
```
