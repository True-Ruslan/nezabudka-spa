# Nepomka v0.2 Service Pages & SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Nepomka v0.2.0 with four production-ready service pages, a broader homepage SEO position, synchronized project documentation, and a release created only from the successfully deployed merge commit.

**Architecture:** Keep the site fully static in Astro 7. Existing `offers` remain the factual source of truth for pricing/mode/short copy; page-specific SEO content lives in a separate typed data module and is rendered by one reusable `ServiceDetail.astro`. Four explicit Astro routes avoid catch-all routing and preserve current `/cases/` and custom 404 behavior.

**Tech Stack:** Astro 7.3.1, TypeScript 5.9.x, Node.js 24, Playwright 1.55.x, plain CSS, GitHub Actions, GitHub Pages, CodeQL.

**Spec:** `docs/superpowers/specs/2026-09-07-v0.2-service-pages-seo-design.md`

## Global Constraints

- Production domain remains `https://nepomka.ru/`.
- Homepage title becomes exactly `Nepomka — автомобильный специалист в Белгороде`.
- New public routes are exactly `/avtopodbor/`, `/proverka-avto/`, `/bronirovanie-plenkoy/`, `/tonirovka/`.
- Keep all six offers on the homepage; only the four key offers receive detail pages.
- Preserve base-path safety for both `/nezabudka-spa/` Project Pages and root custom-domain builds.
- Preserve existing VK/Instagram `target="_blank" rel="noopener noreferrer"` behavior and `tel:` behavior.
- Do not add fabricated reviews, case results, customer counts, certifications, guarantees, or unverified claims.
- Keep pricing/mode/short offer copy in `src/data/site.ts`; do not duplicate it into page configs.
- Service pages remain static and introduce no form, backend, cookies, analytics, CMS, React, or UI framework.
- Tag/release `v0.2.0` only after the merge commit has green post-merge CI and successful production deployment.
