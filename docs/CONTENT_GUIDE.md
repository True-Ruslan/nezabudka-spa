# Content Guide

Этот документ описывает безопасный процесс обновления контента **Nepomka**. Базовое правило: сайт не публикует сведения, которые нельзя подтвердить.

## Контакты

Контактные данные редактируются в `src/data/site.ts`, объект `contact`.

Текущее подтверждённое production-состояние:

- `phone` — опубликован;
- `telegram` — опубликован;
- `instagram` — опубликован;
- `email` — `null`.

Рядом с телефоном публикуется официальный знак MAX как индикатор доступности этого номера в MAX. До появления подтверждённой персональной MAX-ссылки знак не является ссылкой и не подменяется предположительным URL.

Неизвестный или неподтверждённый канал оставлять `null`. Не добавлять временные, служебные или предположительные контакты. Телефон/email/социальные каналы публиковать только после проверки значения и разрешения владельца.

## Offers и страницы услуг

Цены, режим, краткое описание и CTA шести услуг находятся только в `src/data/site.ts` (`offers`). Это factual source of truth.

Page-specific тексты четырёх detail pages находятся в `src/data/service-pages.ts` и не должны дублировать собственные независимые цены/режимы.

Публичные detail routes:

- `/avtopodbor/`;
- `/proverka-avto/`;
- `/bronirovanie-plenkoy/`;
- `/tonirovka/`.

При правке service content:

- не обещать результат, который невозможно гарантировать;
- не превращать стартовую цену `от ...` в фиксированную;
- явно сохранять ограничения и отдельно оплачиваемые элементы;
- не добавлять invented customer counts, reviews, certificates или кейсы;
- после изменения проверять unique title/description/canonical и Service JSON-LD.

## Кейсы

Источник: `src/content/cases/`.

Для нового кейса:

1. Скопировать `case-template.md` в отдельный файл.
2. На этапе подготовки оставить `publish: false`.
3. Заполнять только фактические `title`, `vehicle`, `context`, `summary`, `problem`, `investigation`, `decision`, `rationale`, `result`.
4. Проверить текст с Данилом и исключить раскрытие персональных данных/идентификаторов без разрешения.
5. Только после фактчекинга установить `publish: true`.

`publish: true` создаёт карточку и `/cases/<id>/`; `publish: false` не создаёт public route. `case-template.md` всегда должен оставаться непубличным.

Нельзя добавлять неподтверждённые причины неисправности, придуманные сроки/стоимость/экономию, VIN/госномер/ФИО/телефон клиента без необходимости и разрешения, фиктивный отзыв или любые числа «для убедительности».

## Фотографии и generated visuals

Для документального контента предпочтительны реальные фотографии с понятным правом на публикацию.

`public/branding/danil-hero.webp` допустим как утверждённый брендовый hero visual на основе предоставленных владельцем референсов, но не как доказательство конкретной выполненной работы, события или достижения.

Правила:

- не публиковать клиентские идентификаторы без разрешения;
- смысловым изображениям задавать полезный `alt`, декоративным — `alt=""`;
- оптимизировать размер/формат;
- не использовать generated images как фиктивные доказательства опыта или кейсов;
- не заменять утверждённые production assets без отдельного review.

## Проверка перед публикацией

Node.js 24+:

```bash
npm ci --no-audit --no-fund
npm run check
npm run build
npm run verify:build
npx playwright install chromium
npm run test:e2e
```

Для нового `publish: true` кейса дополнительно проверить `/cases/<id>/`, отсутствие public `case-template`, metadata/canonical и mobile overflow.

Для service-page изменения проверить route, unique metadata, canonical, structured data, contact CTA, base-safe navigation и sitemap.

Deployment выполняется только после successful CI в `main`; Pages workflow после публикации дополнительно проверяет реальную главную, representative service route и custom 404.
